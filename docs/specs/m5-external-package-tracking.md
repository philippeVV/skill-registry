# M5 Spec — External Package Tracking

## Goal

Packages sourced from external repos stay current automatically. A scheduled
CI job checks upstream sources daily and opens PRs when changes are detected.
Every upstream change still goes through human review before landing.

Exit criterion: A tracked external package auto-generates a sync PR when
its upstream changes.

---

## Schema Addition

`metadata.json` gains an optional `upstream` field (already in the JSON
Schema from M1 — this milestone wires up the CI job that uses it):

```json
"upstream": {
  "url": "https://github.com/external-org/their-skills",
  "path": "packages/useful-skill/SKILL.md",
  "ref": "main"
}
```

- `url` — GitHub repo URL
- `path` — path to the artifact file within the upstream repo
- `ref` — branch, tag, or commit SHA to track

---

## Task List

### 1. `renovate.yml` — Scheduled Workflow

Runs daily on a cron schedule.

```yaml
on:
  schedule:
    - cron: '0 6 * * *'   # 06:00 UTC daily
```

Implemented as a JavaScript Action using `@actions/github` and `@octokit/rest`
— the native tooling for GitHub API access in Actions. No Python, no `gh` CLI.

**Steps:**
1. Find all packages with an `upstream` field by reading `marketplace.json`
   (already generated — no need to scan `packages/` manually)
2. For each tracked package:
   a. Fetch upstream artifact via GitHub API:
      `octokit.repos.getContent({ owner, repo, path, ref })`
   b. Decode base64 content from API response
   c. Compare against local `packages/<name>/<artifact>` content
   d. If identical: skip, log `<name> is up to date`
   e. If different: open a sync PR via `octokit.pulls.create`
   f. If upstream unreachable (deleted, private, rate-limited): log warning,
      skip, continue — do not fail the job

**Auth:** `GITHUB_TOKEN` provided automatically by Actions. Sufficient for
public upstream repos. Private upstream repos require an additional PAT
configured as a repo secret.

---

### 2. Sync PR Format

When upstream content differs from local:

**Branch name:** `sync/<name>-<date>` (e.g. `sync/code-review-expert-2026-04-18`)

**PR title:** `chore: sync <name> from upstream`

**PR body:**
```
Upstream source changed: <upstream.url>
Path: <upstream.path>
Ref: <upstream.ref>

Auto-generated by renovate.yml. Review the diff carefully before merging —
this change came from an external source.

If the local version has diverged intentionally, resolve conflicts in favour
of the local version and close this PR.
```

**PR goes through normal `pr.yml` validation and human review before merge.**
The trust boundary is never bypassed.

---

### 3. Conflict Handling

If the local artifact has been modified (drift detected via lockfile hash),
the sync PR will show a git conflict. The reviewer decides which wins:
- Accept upstream: close the PR as-is, merge upstream changes
- Keep local: close the PR, the local version is intentional

No automated resolution — always a human decision.

### 4. Contributor Guide Update

Add `docs/external-packages.md` covering:
- How to import an external package (submit PR with `upstream` field)
- What the Renovate flow does and when sync PRs appear
- How to handle conflicts between local edits and upstream changes
- How to stop tracking an upstream (remove the `upstream` field)

## Key Decisions

| Decision | Choice |
|---|---|
| Trigger | Daily cron (`0 6 * * *` UTC) |
| Upstream fetch method | GitHub API via `gh api` — no full git clone |
| Implementation | JavaScript Action — `@actions/github` + `@octokit/rest` |
| Auth | `GITHUB_TOKEN` (public repos), PAT secret (private repos) |
| Unreachable upstream | Log warning, skip, continue — no job failure |
| Conflict resolution | Always human — no automated resolution |
| PR review | Normal `pr.yml` pipeline — trust boundary preserved |
| Auto-trigger on upstream push | Not possible without a server — polling only |
