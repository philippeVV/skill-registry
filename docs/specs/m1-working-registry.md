# M1 Spec — Working Registry

## Goal

A functional OSS registry where a developer can publish, find, and install
a package. The full pipeline works end-to-end: author a package → open PR
→ CI validates → merge → index rebuilds → `skr install` works.

Exit criterion: `skr install suggest-packages` works against the OSS repo.

### 2. CI — `pr.yml`

Triggers on every PR. No path scoping — always validate.

**Steps:**
1. Detect changed packages (diff against main, find `packages/*/` dirs)
2. For each changed package, run `python ci/validate.py packages/<name>`
3. Fail PR if any validation error

**`ci/validate.py` — two layers:**

Layer 1 — JSON Schema:
- Validate `metadata.json` against `ci/schema/metadata.schema.json`
- Use `jsonschema` Python library

Layer 2 — Semantic rules:
- `name` field matches the directory name
- Artifact file exists and matches the declared `type` (per `package-types.md`)
- `tags` is a non-empty list of non-empty strings
- If `upstream` present: `upstream.url` is a valid URL, `upstream.path`
  and `upstream.ref` are non-empty strings
- Clear error messages referencing the specific field or file

Contributors can run locally: `python ci/validate.py packages/<name>`

---

### 3. CI — `publish.yml`

Triggers on merge to main. Path-scoped:

| Changed path | Jobs triggered |
|---|---|
| `packages/**` | validate → rebuild index → bump version tag → (M4: deploy frontend) |
| `web/**` | deploy frontend only (M4) |
| `skr/**` | (M2+: build binary) |
| `ci/**`, `docs/**` | nothing |

**Index rebuild (`ci/build_index.py`):**
1. Read all `packages/<name>/metadata.json` files
2. Read the latest git tag per package (`<name>@<semver>`) to get version
3. Build a valid `marketplace.json` from all packages
4. Commit `marketplace.json` back to main with message `chore: rebuild index`

**Version tagging:**
1. Read conventional commit messages on the merged PR
2. Determine semver bump: `fix:` → patch, `feat:` → minor, `feat!:` → major
3. If no prior tag for this package: start at `1.0.0`
4. Create tag `<name>@<new-version>` and push

### 4. CI — Renovate Auto-PR (External Package Tracking)

A scheduled workflow (`renovate.yml`) runs daily. It checks all packages
that have an `upstream` field in `metadata.json` and opens PRs when the
upstream has changed.

**`metadata.json` upstream field:**
```json
"upstream": {
  "url": "https://github.com/external-org/their-skills",
  "path": "packages/useful-skill",
  "ref": "main"
}
```

**Workflow steps:**
1. For each package with an `upstream` field:
   a. Fetch the upstream source at `upstream.url`, path `upstream.path`,
      ref `upstream.ref`
   b. Diff fetched artifact against the local committed artifact
   c. If no diff: skip
   d. If diff exists: open a PR with title
      `chore: sync <name> from upstream (<upstream.url>)`
      and the diff as the body
2. PR goes through normal `pr.yml` validation and human review before merge
3. If the local version has diverged from upstream (via local edits), the
   PR will show conflicts — reviewer decides which wins

The trust boundary is never bypassed: every upstream change requires human
approval before landing.

### 5. `skr` CLI

**Module:** `skr/go.mod` — `module github.com/org/skill-registry/skr`

**Install:** `go install github.com/org/skill-registry/skr@latest`

**Config file:** `~/.config/skr/config.toml`
```toml
registry = "https://github.com/org/skill-registry"  # default
claude_config_dir = "~/.claude"                       # default
otel_endpoint = ""                                    # empty = disabled
```
Env var overrides: `SKR_REGISTRY`, `OTEL_EXPORTER_OTLP_ENDPOINT`

**Index cache:** `~/.config/skr/cache/marketplace.json`
- TTL: 1 hour
- All read commands use cache; fetch+refresh if stale or missing
- Offline: use cache regardless of TTL if network unavailable
- `skr update` forces refresh

**Lockfile:** `~/.config/skr/skr.lock`
```json
{
  "registry": "https://github.com/org/skill-registry",
  "packages": {
    "suggest-packages": {
      "version": "1.0.0",
      "type": "skill",
      "location": "~/.claude/skills/suggest-packages.md",
      "hash": "sha256:abc123...",
      "registry_hash": "sha256:abc123...",
      "installed_at": "2026-04-18T10:00:00Z"
    }
  }
}
```
- `hash` — SHA256 of the currently installed artifact
- `registry_hash` — SHA256 at install time from the registry
- Drift: `hash != registry_hash` → `skr list` shows `[modified]`

**Install placement** (resolved after type research spike):
- Defaults per type defined in `docs/package-types.md`
- `install_target` in `metadata.json` overrides type default
- `claude_config_dir` from config is the root for all Claude paths
- Resolution order: `install_target` → type default → `claude_config_dir`

**Commands:**

```
skr install <name>[@version]
  - Refresh cache if stale
  - Resolve package from index
  - Place artifact at correct location
  - Write lockfile entry

skr install --tag <tag>
  - Filter index by tag
  - Install all matching packages in sequence
  - Same placement and lockfile logic as single install

skr uninstall <name>
  - Remove artifact file (or fence block for claude_md target)
  - Remove lockfile entry

skr list
  - Read lockfile
  - For each package: show name, version, type, [modified] if drifted

skr search <query>
  - Use cached index
  - Match against name, description, tags (case-insensitive substring)
  - Print name, type, description, tags per result

skr info <name>
  - Use cached index
  - Print full package detail: all metadata fields + trust signals
    (stats fetched live from OTEL if endpoint configured)

skr update [<name>]
  - Force cache refresh
  - For each installed package (or named package): check if newer version
    in index, reinstall if so

skr --registry <url> <cmd>
  - Override registry source for this invocation only
```

### 6. Testing

**Unit tests** — pure functions in `skr/`:
- Index parsing and search
- Version resolution
- Lockfile read/write/drift detection
- Config parsing

**E2E tests** — filesystem interaction:
- Create a temp directory mimicking Claude config structure before each test
- Set `claude_config_dir` to temp dir via config override
- Run install/uninstall/list against temp dir
- Assert file contents, placement, lockfile state
- Load index from fixture `marketplace.json` files — no live network calls

Standard Go `testing` package. No external framework.

## Key Decisions Summary

| Decision | Choice |
|---|---|
| CI | GitHub Actions |
| Indexer | Python (`ci/build_index.py`) |
| Validator | Python with JSON Schema + semantic rules |
| CLI language | Go, standalone module at `skr/go.mod` |
| CLI distribution | `go install` from source |
| Index cache | Local, 1h TTL |
| Versioning | CI-owned semver via GitHub tags + conventional commits |
| Package namespace | Flat — `packages/<name>/` |
| Install scope | User-level by default |
| Type-specific placement | Defined in `docs/package-types.md` (research spike) |
| Lockfile | `~/.config/skr/skr.lock` with hash-based drift detection |

Full rationale for each decision: `docs/design/adr/`
