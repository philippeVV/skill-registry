# ADR-019: Repository Structure

**Date:** 2026-04-18
**Status:** Accepted

## Context

The OSS repository serves as both the registry software (CLI, frontend, CI
scripts) and the marketplace (the actual packages and index). These concerns
need a clean top-level layout before implementation begins.

## Decision

```
/
├── marketplace.json        # generated by CI — the agentskills.io index
├── packages/               # registry content
│   └── <name>/
│       ├── SKILL.md        # (or RULE.md / KNOWLEDGE.md)
│       ├── metadata.json
│       ├── README.md
│       └── eval/
│           └── scenarios.yaml
├── skr/                    # Go CLI source
├── web/                    # Astro frontend
├── ci/                     # index rebuild script, gate pipeline scripts
└── docs/                   # all documentation
    ├── VISION.md
    └── design/
        └── adr/
```

`marketplace.json` lives at the repo root because that is where Claude Code's
native `/plugin marketplace add <repo-url>` expects it.

All documentation — vision, ADRs, future specs and guides — lives under
`docs/`. No docs scattered at the repo root.

## Consequences

**Positive:**
- Clear separation between registry software, content, and documentation
- `marketplace.json` at root satisfies the native `/plugin` convention with
  no configuration
- `docs/` as a single documentation home scales cleanly as the project grows

**Negative:**
- None significant

**Neutral:**
- VISION.md and ADRs move from their current locations to `docs/` and
  `docs/design/adr/` respectively
